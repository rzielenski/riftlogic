Rift Logic Reference

Overview

Rift Logic is a small C++-style language for making claims about League of Legends that can be checked against the game's own data. It has three kinds of answer:

  • Calculations: damage, healing, stats, cooldowns, projectile travel times, from the formulas the game ships with.
  • Simulations: timed fights between champions or team comps, with runes, item passives, heals and shields.
  • Arguments: rules that argue for or against a claim like beats(Fizz, Syndra), where the strongest argument wins.

Every result shows its working and lists every assumption the model made. A result is only as good as those assumptions, which is why they're always visible.

Running programs

In the editor, results update as you type (Ctrl/⌘ + Enter re-runs). Click a row in the results to see its working, assumptions and tables. The Inspect tab shows any champion's or item's data, including every named formula you can reach.

From the command line, the same engine runs a file:

node tools/rl.js program.rl           # full working for every result
node tools/rl.js program.rl --brief   # one line per result
echo 'print(Syndra(11).Q.damage);' | node tools/rl.js -

The exit code is 0 when every assert and prove held, 1 when anything was refuted or errored, and 3 if the engine itself crashed, so programs can be used as checks. --max-ms=60000 adds a time limit (the editor uses 3 seconds while you type, 10 seconds for Run or Ctrl/⌘ + Enter); --usage prints how much of each limit below the program used.

Imports (command line only): import "../lib.rl"; at the top of a file pulls in another program's functions, rules, variables and data corrections. Paths are relative to the importing file, each file is imported once, and the imported file's own assert/print/prove output is not shown. The reasoning workspace (reasoning/) uses this to share scenario comps and rules between questions.

A first program

ItemSet burst = {Ludens, Sorc};
Champion a = Syndra(11).with(burst, Electrocute);
Champion tank = Garen(11).with(Plated, Kaenic);

assert(a.Q.damage(vs: tank) > 150);          // Proved or Refuted, with the formula
print(a.ap, a.Q.cd, a.combo(Q, E, R, vs: tank));
assert(canKill(a, tank, 5), "Syndra kills Garen in 5 seconds");

Names: champions, items, runes

A capitalised name that isn't a variable is looked up in this order: classes (Mage), summoner spells (Flash, Ignite, …), champions, exact rune names, items, then rune name prefixes. Lower-case names are variables or ability tags (stun, dash).

  • Champions are written without spaces or punctuation: KSante, MissFortune, Wukong. Syndra alone is Syndra at defaultLevel with no items; Syndra(11) sets the level.
  • Items accept any unique start of the name: Ludens, Rabadon, Sorc, Plated. An ambiguous prefix is an error that lists the matches.
  • Runes by name, without spaces: Electrocute, SuddenImpact, AdaptiveForce, HealthScaling.
  • Ability slots P Q W E R are used in combo(Q, E, R).
  • Globals: defaultLevel (11) and gameMinute (20) can be assigned.

Functions and control flow

double burstOn(Champion c, Champion t) {
    return c.combo(Q, E, vs: t) + c.proc(Ludens, vs: t);
}
bool oneShots(Champion c, Champion t) { return burstOn(c, t) >= t.hp; }

for (Champion c : blue) if (c.is(Mage)) mages++;
for (int i = 0; i < 5; i++) { … }
while (x < 10) { … }             // break and continue work as usual

Functions can be declared anywhere at the top level and called before their declaration. Parameters need types; a function with a return type other than void must return. break and continue outside a loop are errors.

Limits. So that a runaway program ends with an error instead of freezing the page or running out of memory, every run has these limits (the same in the editor and on the command line):

  • 3,000,000 steps (“program stopped after 3,000,000 steps — infinite loop?”); the program stops.
  • 200 nested function calls (endless recursion), and brackets or blocks nested too deeply to read.
  • A list, TeamComp or Combo holds at most 100,000 values (“a list can hold at most 100,000 values …”); that statement fails.
  • 2,000,000 values created in one run: list and TeamComp elements (copies included; assigning a list copies it), champion copies and combo steps. A list that copies itself into itself doubles every round and hits this after about twenty rounds; the program stops.
  • 10,000 results (print, assert, prove); the program stops.
  • perform plays combos of up to 10,000 steps; a fight lasts at most 120 seconds; fights(…) runs at most 5,000 fights.
  • Steps count your program’s own work, not the simulation: a fight() call costs a few steps however long the fight is, and the fights inside a fights(…) sweep cost none (only its role functions do, once per level and team). The same sweep written as a loop also pays for the loop and for re-running the role functions before every fight (about 20 times the steps), so use fights(…) for sweeps.
  • Strings up to 1,000,000 characters.
  • The working under one result is cut after 5,000 lines, and after 200,000 lines in the whole program (a note marks the cut); the values are unaffected.
  • Time (for example a loop of fights): in the editor 3 seconds while you type and 10 seconds for Run or Ctrl/⌘ + Enter; none on the command line unless --max-ms= is given.

Rune

Runes go into with() or a.runes.add(). Shards can be repeated: .with(AdaptiveForce, AdaptiveForce, HealthScaling). Conqueror.description returns the rune's text, which is where its numbers come from. runes() lists every rune. See Modelled runes for which ones change stats and which act in fights.

Summoner spells

Flash, Ghost, Heal, Barrier, Ignite, Exhaust and Cleanse are values of type Summoner. Give a champion two with x.with(Flash, Ignite) or x.summoners = {Flash, Ignite};. A champion without any set is assumed to have whichever one you use (the result says so).

Combo c = {Flash, Q, W, Ignite};
print(Annie(11).perform(c, vs: Dummy(hp: 3000)).damage);

Fight sweeps

One fight() is one cell, and its winner can flip when the start distance moves by 100 units or a role changes. fights(…) runs fight() over every start × level × role set and gives the share with an interval, so a claim can rest on the sweep instead of one cell. Example: Fight sweeps in the editor.

TeamComp engage(TeamComp t, int level) {   // a role set: gets each team at each level, returns it ready to fight
    for (Champion& c : t) if (c.name == "Renekton" || c.name == "Jarvan IV" || c.name == "Rakan") c.role = "engage";
    return t;
}
Fights s = fights(poke, red, 40, starts: range(0, 1200, 100), levels: {9, 13, 16}, roles: engage, bothSides: true);
print(s);   // … 50-0-28 of 78, share 64.1% (95% CI 53.0%–73.9%), decided in 12.96s on average, 0 side-swap mismatches
print(s.byLevel(9).share, s.byLevel(16).share, s.byStart(400).wins);   // 0.77  0.54  0

In this engine, at equal level and gold, a "scaling" comp is simply its champions at those levels and items. Gaps are how you test the game state a draft is aiming for. The fights are deterministic but not guaranteed to be monotone: over a few starts, one more level can still flip a single cell the other way. Sweep enough starts, or read crossover's trace, before trusting one gap.

Printed, a sweep is one line; its detail (and the working of any s.… value) is a grid with one square per start for each role set, level and side order, so you can see where the result flips. At most 5,000 fights per sweep. The fights inside a sweep cost no steps (only the role functions do, once per level and team); they count against the time limit, about 15–25 ms per 5-v-5 fight of 40 s.

Combo

A combo is an exact sequence of abilities and auto attacks, run through the fight simulator against one target, so every proc applies: spellblade after abilities, Electrocute on the third separate hit, Luden's, on-hit items, crits, burns, and the target's shields, Zhonya's and healers.

Real-game stats

Everything else in Rift Logic is computed from the game files. These functions instead read what happened in real games: ranked solo queue by default, pro play with pro: true. Each returns a Stat: a number together with its sample size and a 95% interval, printed like 51.2% (n 7,713; 95% CI 50.1–52.3%). If there are too few games, it says so instead of giving a noisy number. Example: Real-game stats in the editor.

print(winrate(Syndra, vs: Orianna));                 // 54.4% (n 241; 95% CI 48.0–60.5%)   any roles
print(winrate(Syndra, vs: Orianna, lane: true));     // 53.3% (n 167; 95% CI 45.7–60.7%)   same lane
print(winrate(Syndra, with: Nautilus));              // 49.9% (n 675; 95% CI 46.2–53.7%)   same team
print(winrate(Syndra, vs: Orianna, pro: true));      // 43.7% (n 142; 95% CI 35.8–51.9%)
print(presence(Syndra, pro: true));                  // 29.2% (2,638 picks or bans in 9,026 games; 95% CI 28.3–30.2%)

Win probability and WPA (pro)

Win rate only says whether a champion's team won. Win probability added (WPA) asks how much the team's chance of winning moved while the champion played, and credits the champion with a share of that move. It needs a model of the chance of winning at each point of a game: winprob(). The idea follows Coachless, who describe a calibrated in-game win probability model; theirs isn't published, so this one is built here from Oracle's Elixir by src/winprob.py (run it for the full validation report, --gbm for the gradient-boosting comparison).

print(winprob(goldDiff: 1000, at: 10));                 // 0.69

The model

  • What it predicts: P(team wins | what is known at minute t) for t = 10, 15, 20, 25: one logistic regression per minute on Oracle's Elixir games, fitted from blue's point of view (red's probability is exactly 1 − blue's; a neutral side drops the side term). Minutes between the snapshots interpolate the coefficients.
  • Features (the full model): gold and XP differences per position (per 1,000; each player against the same-position opponent), the team's kill difference, the team's CS difference (per 100), and three things known before the game:
    • Team strength: the pre-game Elo difference / 400 (the ratings of the draft model, updated only after each game).
    • The draft: the pro draft model's logit for the two drafts at equal ratings and without its side term. Each year's games are scored by a draft model fitted only on the four years before (2026 by 2022–2025, 2025 by 2021–2024, …), so the in-game model learns how much an out-of-sample draft prediction is worth, and the draft term never carries team strength (ratings are a separate term).
    • Comp scaling: each champion's scaling score is the slope of its win rate (log-odds per 10 minutes) against game length in ranked solo queue (games of 15+ minutes, shrunk to the mean by empirical Bayes: a champion with few games stays near 0); a team's score is the sum over its five champions, and the feature is blue's minus red's. Highest: Bel'Veth +0.27, Kassadin +0.22, Azir +0.21, Ornn +0.19, Yuumi +0.19, Kha'Zix +0.17; lowest: Locke −0.23, Irelia −0.18, Hecarim −0.17, Nidalee −0.17, LeBlanc −0.15. It is a champion attribute measured on solo games (like the hand-labelled comp profiles), not a solo-queue model: the pro model is fitted on pro games only. The same slope measured on pro games (earlier years only) made the model worse: pro game length is mostly team strength. The hand label (the "scaling" archetype in labels/draft_profiles.csv) helped about half as much.
    The scaling term has its own weight at each minute, so the model learns how scaling matters as the game goes on: 0.30 at 10 minutes, 0.47 at 15, 0.63 at 20, 0.74 at 25 (logit per unit of scaling difference). A gold × scaling interaction (a lead worth less against a scaling comp) was tested and changed nothing out of sample, so it isn't used: the scaling comp's edge is a shift that grows with time, not a discount on the gold.
  • What it can't use, and why: towers, dragons, heralds, barons, Atakhan and "firsts" are in Oracle's Elixir only as whole-game totals. A game's dragon count includes the dragons taken after minute t, which is part of what the model predicts, so using them would leak the result; none is used. Void grubs are the exception whose total is complete by 20 minutes (the pit turns into Rift Herald's); they were tested at 20 and 25 minutes and added nothing beyond the gold they bring. Assists added nothing either. Items, wards and objective timers aren't in the data at all. The solo-queue model will be separate and built from Riot timelines, which do have objectives and items at every minute (stats.json keeps winprob.solo for it).

How WPA is credited

  • The team's path: side prior (53.0% blue) → the draft model's pre-game probability at equal ratings → the in-game model at 15 minutes without its rating term → the result (1 or 0). Over a game a team's WPA is result − prior, so the two teams' WPA adds up to zero, phase by phase.
  • Draft phase: the change from the side prior to the pro draft model's probability for the two drafts (below), at equal team ratings (team strength is not something a pick adds). Each game is scored by a draft model fitted only on the four years before it (2026 games by the 2022–2025 fit, 2025 games by 2021–2024), so a champion's own results don't leak into its draft value. The draft logit is written as a sum of five per-role terms from blue's point of view (red's are the negatives): the champion's strength minus the opponent's, the lane-matchup term, half of each synergy pair it is in, and its Shapley share of the team's comp-profile score (averaged over every order of adding the five picks, with open slots at the role's typical profile). These five terms are split by Shapley values of sigmoid(side term + the terms in a coalition) − the side prior. Lane opponents get exactly opposite draft WPA. The part of a change that no player causes is split equally.
  • Lane phase (draft → 15 min): the change from the draft probability to the rating-neutral 15-minute probability, split among the five players by Shapley values. Each player's contribution to the team's 15-minute logit is the full model's weights for their position times their own gold and XP differences against the same-position opponent, plus the kill weight times their kills minus the opponent's and the CS weight times their CS difference (Oracle's Elixir golddiffat15, xpdiffat15, csdiffat15, kills at 15; the five add up to the team's). The draft and scaling terms of the 15-minute model are the fixed part; the difference between them and the draft probability is split equally, like any change no single player causes.
  • Team phase (15 min – end): result − the rating-neutral 15-minute probability, split equally (a fifth each). It holds what happens after 15 minutes and team strength: the rating term is left out of the 15-minute point on purpose, so a strong team's expected edge lands here and is never credited to a champion's draft or lane. Oracle's Elixir's 20- and 25-minute differences are per position too, but after laning they reflect whoever took the gold in fights, so no per-player split is attempted.
  • Total = draft + lane + team. A champion's number is the mean over its games with 15-minute data (games without it, mostly some LPL and LDL games, are left out, so the n is a little below the win rate's). Means below 20 games are too little data; vs: pairs are stored from 20 games.
  • What the new model changed (2026, before → after): Syndra total +0.55 → +0.43 pp, lane +1.26 → +1.03, team −0.40 → −0.28 (draft −0.31, unchanged); Syndra mid +0.55 → +0.41; Orianna mid +2.52 → +2.46 (lane +1.13 → +1.46); LeBlanc mid lane +3.89 → +4.28, team −1.17 → −0.96; Mel mid +2.41 → +3.56 (lane +4.36 → +5.54); Azir mid −1.51 → −1.72; Taliyah mid −0.89 → −1.32. Mid and bot leads now weigh more than top and jungle leads, and scaling comps' teams are expected to do better after 15 minutes, so less of their late wins counts as team WPA.

Limits

  • Team strength still reaches the total. It is kept out of the draft and lane phases, but a champion that strong teams play still gets their wins in team WPA. WPA is better than win rate at showing where a champion helps (a lane-winning pick that falls off, like LeBlanc, looks different from one that scales), but it is still observational.
  • Coarse snapshots. Oracle's Elixir gives the state only at 10, 15, 20 and 25 minutes, and no objective, item or vision state at the snapshot (see above). Two teams with the same gold lead can be in very different games.
  • Pro only. Solo queue gets its own model from Riot timelines (objectives, items and gold at every minute); until then wpa() and winprob() say "needs timelines; not available yet". stats.json keeps the slots ready: winprob.solo next to winprob.pro (each model lists its own features and variants), draftwp.solo next to draftwp.pro, and the solo dataset will get the same wpa/wpaDraft/wpaLane/wpaTeam averages.
  • The draft phase is small: a champion's draft WPA is nearly the same every game (its strength term dominates), so its interval is narrow, but it is a model estimate, not a measured effect.
  • The model behind WPA is fitted on all years, including the 2026 games it scores. Every league is pooled; a lead is probably worth more in a top league, where it is converted more reliably. The scaling scores come from 2026 solo-queue games and are applied to every year's champions (a reworked champion keeps its current score).

Draft win probability (pro and solo queue)

Who wins, given only the picks? draftwp() answers with a model fitted on real games, and pickwpa() says how much one pick moves it. Pro play and solo queue are different games (coordinated teams and a known team strength vs five strangers), so each has its own model, fitted separately: pro: true picks the pro one. They are built by src/draftwp.py (run it for the validation report) into stats.json, and the Draft page uses the same coefficients. Example: Real-game stats in the editor.

The model

  • Form (both): logit P(blue wins) = side term + Σ over roles [strength(blue champion, role) − strength(red champion, role)] + Σ lane matchup(blue, red) + synergy(blue) − synergy(red) + w · (profile(blue) − profile(red)), plus, in pro, wR × (Elo blue − Elo red) / 400. Every term is antisymmetric, so swapping the sides gives exactly 1 − P apart from the side term.
  • Champion strength = a champion main effect + a champion-by-role deviation. Lane matchups: one antisymmetric term per same-role pair with 15+ (pro) or 30+ (solo) games. Synergy (pro only): bot + support, jungle + support and jungle + mid pairs with 15+ games; in solo queue they made held-out predictions worse, so the solo model has none. Comp profile (labels/draft_profiles.csv, the Draft page's hand profiles): shortfalls in frontline (below 2), engage + ½ pick (below 3.5), carry (below 4.5) and ranged threats (below 2), too much frontline (above 3), a damage mix outside 28–62% magic, class stacking, five melee, the poke × protect mix, and the archetype shares. These carry signal for pairs too rare to have their own term.
  • Fitting: L2-penalised logistic regression (sklearn) with a separate penalty per group, chosen on a validation split inside the training data (pro: fit 2022–2024, validate 2025; solo: first 70%, validate the next 15%). Pro games are weighted by recency (half-life one year) and the pro model starts in 2022. Heavier models weren't tried: the gains below are already at the size where the logistic form is not the limit.
  • Pro team ratings: Elo over every Oracle's Elixir game 2019–2026 in date order, K = 64 (tuned on 2025: log loss 0.634 against 0.642 at K = 16), updated only after each game, so a game sees only earlier results. A new team starts at the mean rating of its league's teams; each new year ratings move 25% back toward the league mean; international events don't change a team's home league. The rating weight is fitted together with the draft terms (1.68 logit per 400 Elo), so the champion terms mean "at equal team strength". blueRating: takes an Elo number or a 2026 team name (the table as of 2026-09-22; e.g. Gen.G 2115, T1 1900). Ratings compare well within a league and across leagues only through international games; small circuits can drift.
  • Partial drafts: an open slot counts as the role's pick distribution (pro: 2026 pro picks by position; solo: ranked solo 16.x by teamPosition): its expected strength, the lane term against a known opponent averaged over the open side's distribution (0 when both are open: antisymmetric), synergy likewise, and the role's average profile in the comp features. P = sigmoid of that expected logit. So the empty draft is exactly the side prior, and a pick's WPA is P(after) − P(before): the WPAs of a whole draft, in order, add up to the full draft's P − the side prior (tests/draft_wp.rl). Bans are not in the model, and an open slot's distribution doesn't exclude champions already picked. Roles are inferred by the most likely assignment (the product of each champion's share in each role) unless byRole: true.

Limits

  • Small effects. A pick typically moves the pro model by under ±1 pp and the solo model by under ±3 pp. Treat differences of a few tenths of a point as noise.
  • Confounding. The model learns which drafts won, not why. In solo queue a champion's strength term includes who plays it (one-tricks, rank); in pro, the ratings remove team strength only as far as Elo captures it (rosters change mid-year, and minor-league ratings are only linked to major ones through international games).
  • No game plan. The model doesn't know what a comp intends. The Draft page keeps its needs and game-plan logic and blends the model in (next paragraph).
  • Draft page blend: each suggestion shows its pick WPA from the mode's model (pro or solo) as "WP ±x", the header shows the side's current win chance and each comp panel a "Win prob." row. The ranking adds 1 × the pick WPA (in pp) to the heuristic score when the model's held-out calibration error is under 1.5% (both models today: pro without ratings 0.8%, solo 0.7%), otherwise ½ ×. Ban ideas show what the enemy would gain by picking the champion. The pro page uses equal team ratings.

Reading them carefully

  • Solo-queue win rates are observational. A champion's win rate mixes in who picks it (mains and one-tricks win more on hard champions; weaker players drift to others), what else is in the draft, and blind or counter picks. A matchup win rate is not a counter by itself: the champion picked second often picked because it counters.
  • Pro win rates carry team strength. Strong teams get the meta champions and win anyway; every league from LCK to minor regions is pooled, and samples are small. Presence (picks + bans) is the more reliable pro signal of how highly a champion is rated.
  • Small samples. Read the interval, not the point: 53.3% (n 167; 95% CI 45.7–60.7%) is consistent with an even matchup. matchups() and topPicks(by: "winrate") list the extremes, which are where small samples land; use min:.
  • Every result's working says which games it counted, and the footnotes name the dataset and these caveats.

Rules and claims

rule dive(Champion x, Champion y) -> beats(x, y) [1] {
    return x.is(Assassin) && x.has(mobile) && !y.has(mobile);
}
rule stunTheDive(Champion x, Champion y) -> !beats(x, y) [2] {
    return x.has(mobile) && y.has(stun);
}
prove beats(Fizz, Syndra);
  • A rule is an argument that the claim is true (-> beats(x, y)) or false (-> !beats(x, y)) whenever its body returns true. [n] is its strength, default 1.
  • For a claim, every rule with that name and number of arguments is tried. The strongest argument that fires wins. If the strongest for and against are equally strong, the claim is contested. If none fire, no rule applies.
  • A body written as return c1 && c2 && c3; is shown condition by condition, with the evidence for each (the tooltip phrase behind a tag, the formula behind a number). Other bodies are shown as a whole.
  • Claims can be used inside functions and other rules as booleans: beats(a, b). A claim is true only when it's proved. Sub-proofs are shown nested.
  • Rule arguments are the parameter names in the claim, in order: -> counters(y, x) is allowed.

Physics and dodging

canDodge(defender, ability, distance: d, using: defender.X, reaction: r, preBuff: bool, recast: bool, hitbox: units) checks whether the defender can avoid an ability aimed perfectly at them from d units away.

Where it comes from. Range doesn't always mean the ability travels from the champion to the target. Every ability has a delivery (a.Q.delivery), read from the game files' targeting type and corrected by hand where they mislead (each correction cites its source):

  • Arrival time (a.Q.arrival(distance: d)) is measured from the start of the cast, by the delivery's formula above.
  • Time to respond = arrival time − the moment it becomes visible − reaction time (default 0, perfect play). It becomes visible when the cast ends (the missile or ground marker appears then; during the cast time the target point can't be seen), unless its data says it shows later (Rumble R: nothing is on the ground until the first rockets land). So Syndra Q gives 0.6 s to respond at any distance.
  • Hitbox: the defender's gameplay radius (b.hitbox: 65 for most champions, 80 for large ones, 55 for small ones). Test a grown champion with hitbox: 100.
  • Out of reach — the reach rule (one rule for canDodge, fight() and combos; a.Q.reachTo(b) prints it): the greatest centre-to-centre distance at which something hits b. From the wiki's Range page (Calculations, Targeted abilities), each ability page's range icon (centred cr or edge er), and the game files' castRangeUseBoundingBoxes flag on the spell record — the three agree on every point-and-click damage ability but Twitch R (whose bolts are his attacks) and Bel'Veth R (a Void Coral, not a champion):
    • Basic attacks: edge range, always: attack range + the attacker's radius + the target's. Annie (radius 55) attacks Syndra (65) from 625 + 55 + 65 = 745.
    • Point-and-click spells: centred range: the cast range, whatever either champion's size. Annie Q (625) reaches Syndra at 625 but not at 626.
    • …except edge-range spells (castRangeUseBoundingBoxes: Tristana E/R, Vayne E, Viktor Q, Ryze W/E, Anivia E, Lucian Q, Jhin Q, Quinn E, Poppy E, Senna Q, Zilean E, Janna W, Evelynn E, Singed E, Smolder Q, Cho'Gath R, Nunu Q, Rek'Sai E, Elise Q, Jayce E, Miss Fortune Q, Bel'Veth R): range + both radii. The flag also sits on two self-centred searches (Kennen W, Kai'Sa Q); what it means there isn't verified (the wiki gives Kennen W 775 centred, "pending for test"), so they stay centred. Vayne E reaches Syndra at 550 + 65 + 65 = 680.
    • Everything else (skillshots, areas, cones): centre to edge: its reach (.reach) + the target's radius. Exception: a skillshot whose wiki page marks the game files' range with the centred-range icon ({{tip|cr}}, e.g. Zed Q 925, Ezreal Q 1200) reaches only that far (the target's centre must be within it); one marked edge range ({{tip|er}}, e.g. Yone R 1000, Akali E 825) adds both radii.
    • Hits that are basic attacks (Twitch R): the attack range + the bonus (+300) + both radii.
    • A point-and-click ability without a cast range of its own (an empowered attack) uses the attack reach.
    Beyond that distance the defender is safe standing still.
  • Walking: the defender must move half the width (lines), the radius (areas) or the cone's half-width at that distance, plus their hitbox, before it lands. Move speed includes boots and other items, runes and League's soft caps (b.ms). For an area centred on the caster, they walk out of it instead. The line prints the move speed that would be needed.
  • Point-and-click abilities can't be walked out of.
  • using: an ability that makes the defender untargetable or invulnerable dodges anything if its cast time is shorter than the time to respond. A dash or blink adds its distance (after its cast and travel time), then the defender keeps walking. A move-speed boost (Orianna W, Hecarim E, Singed R, Ghost, Heal, …) starts after its cast: the defender stands still while casting, then walks at the boosted speed (with its decay, ramp or field, and League's soft caps above 415). Perfect play: the defender uses whatever moves it farthest, so a boost whose cast costs more than it gains is skipped and plain walking counts.
  • preBuff: true: the move-speed boosts in using: were cast before the ability appeared, so they're already running (fresh) when the time to respond starts, and cost no cast time. For an invisibility ability (Akali W) it means she's already unseen in the shroud: a point-and-click spell can't be cast on her (wiki Invisibility). Without it, a point-and-click spell cast before she's invisible still lands.
  • recast: true: the using: ability is on its recast. Akali R's recast is an 800-unit dash at 3000/s with no cast time (in any direction); her first R is a 750-unit dash at 1500/s after a 0.25 s cast. Akali E's first cast flips her back 400 units, starting 0.15 s into the cast, at 1500/s.
  • Stacking fields (Viktor W): what must be dodged is the stun on the 5th stack, 2.0 s after the cast starts (placed at the end of the 0.25 s cast, active 0.75 s later, a stack every 0.25 s inside). The defender must be outside (radius 340 + hitbox) by then, and is slowed while inside once the field is active.
  • Viktor R: after the answer, the working adds how many of the storm's 6 strikes land if the defender walks straight away (the storm follows at 300/s within 300 units of Viktor, down to 200/s at 900).
  • Several at once: using: {o.W, Flash} tries every combination of the listed abilities and summoner spells (boost casts first, then dashes and blinks, then walking) and uses the best. using: Flash adds a 400-unit blink with no cast time.

setPhysics also takes delivery: "placed" (or any of the above), origin: (units from the remote object to the target), length: (a vector's length), reveal: (seconds into the cast when it becomes visible) and reach:.

Speeds, widths, radii and cast times come from the game files; where only the wiki has a value (some radii and dash speeds), the result lists it as an assumption. Dash speeds and appear delays that neither source has default to 1200 units/s and 0, also listed as assumptions and settable with setPhysics.

How fights are simulated

  • Time moves in 0.05-second steps. Within a step everyone acts at once, on the state at the start of the step: first items, summoner spells, heals and shields, then everything else. Damage between the sides (and the healing it causes), deaths, walking, blinks, new crowd control (and the interruptions it causes), stasis and knockbacks take effect at the end of the step. So the order of the champions, and which side is side 1, doesn't change the result: a mirror match ends even, and fight(a, b) is fight(b, a) with the sides swapped (tests/fight_symmetry.rl). Two champions can kill each other in the same step. The line is centred on 0 (side 1's front at −start/2) so mirrored positions are exact.
  • Each champion, when free, first uses a heal or shield if an ally needs one (healing ultimates are saved for allies below 40% health), then peels (below), then the first ability in its rotation that is off cooldown and in reach, otherwise an auto attack if the target is in attack range, otherwise it moves. Casting locks the champion for 0.25 seconds. See Crowd control and positions.
  • Damage goes through amplifiers, resistances after penetration, Bone Plating and shields, then health. Lifesteal (attacks), omnivamp and Conqueror heal the attacker; grievous wounds cut healing received by 40%.
  • Heals go to whoever the healer's policy picks; team heals reach everyone; Moonstone chains 30% to a second ally.
  • Zhonya's (below 30% health, or when x.stasis says) puts a champion in 2.5 seconds of stasis; Guardian Angel revives once after 4 seconds.
  • Untargetable from the cast: Zed R (0.95 s), Fizz E (1.25 s), Vladimir W (2 s), Master Yi Q (0.94 s), Kayn R (1.35 s) and Pantheon E (1.5 s, his block) have no cast time, so their casters act first in a step and are untargetable for that whole step: nothing cast at them that step lands (and it neither starts nor cancels First Strike), and an Ignite or Exhaust pressed on them that step is taken back. Hits already in flight that arrive that step still land. Elise's spider-form E isn't modelled.
  • Energy (Zed, Akali, Lee Sin, Kennen, Shen; game data): 200 maximum (Shen 400), +10 per second; abilities wait until it covers their cost, in fights and combos (wait: false skips them instead). Restores: Zed's double hits with a shadow (30–50), Lee Sin's Flurry attacks (20/30/40 then 10/15/20; Q2 costs 25), Kennen E (40) and his passive stun (25), Shen Q/E (30/40/50), Akali W (100, +100 maximum while the shroud lasts). Mana is still ignored.
  • Summoner spells (only for champions with .summoners set, or as combo steps): Ignite and Exhaust once the target is within cast range (650 / 600), Heal and Barrier below 30% health.
  • Viktor and Akali (wiki, checked 2026-09-24; fight() only, perform() keeps the simpler combo rules): Viktor's Gravity Field is placed on the target, activates 0.75 s after the cast and stuns only a unit still inside on its 5th stack (every 0.25 s); fighters walk out at the last moment that still makes it and wait at its edge while the next stack would stun. Aftershock can be sidestepped by a free enemy (it spends the time walking). The storm follows its target at 200–300/s. Turbocharge and Magnetize work. Akali spends energy (200, +10/s; Q 110–70, E 30), casts W (move speed, energy, invisibility: no attacks or point-and-click spells on her while unseen) when she needs energy, to leave a Gravity Field, or first if her rotation starts with W; her E flips her back 400 units and the recast dashes to the marked target; R1 dashes 750 through the target; R2 is used when it kills, at the 70%-missing cap, as its window closes or to escape a field; she steps out of her ring for Swinging Kama.
  • The fight ends when one side has nobody left, or at the time limit.
Positions are on one line; attacks, point-and-click abilities and dashes in reach hit, and skillshots and areas hit unless the defender's player skill lets it walk out (skill: / x.skill, default 70; perfectAim: true = everything in reach hits), an ability lands after its cast time, flight and appear-delay (the timing .arrival and canDodge use: Lux Q at 500 units 0.67 s, Lux R 1 s; cooldown and cost start at the press; crowd control never cancels a cast time (wiki Cast time: only death does) but does cancel channels and charges; dashes start when the cast time ends and hit when they arrive in reach; a displacement or knockdown stops a dash under way, a stun doesn't; unstoppable abilities (Malphite R, Vi R, Hecarim R, Jarvan IV R, …) ignore displacements and can't be stopped, though spell shields still block them; perform() without distance: counts no flight), mana is ignored (energy is not), every champion fights at its own level and items unless levelGap: / goldGap: offset them (a gold gap removes items from the last one bought; a partly-bought item gives only its share of stats), and special mechanics beyond an ability's tooltip formula aren't simulated. Use canDodge and your own rules to reason about the rest.

Crowd control and positions

Positions

  • One line, centred on 0. Side 1's front is at −start/2 and faces +; side 2's front is at +start/2 and faces − (start: default 0). Each champion stands max(0, attack range − 175) behind its front, so ranged champions start at their attack range from where the enemy front will be (formation: false: everyone on the front line).
  • Reach (wiki "Range"): basic attacks use edge range (attack range + both gameplay radii); point-and-click abilities centred range (edge range, + both radii, for the castRangeUseBoundingBoxes spells); other abilities their reach (.reach) + the target's radius. Placed and lobbed areas hit every enemy within their radius of the target; self-centred areas every enemy within the radius of the caster; lines and cones every enemy within reach (on one line everything is in the path).
  • Walking uses the current move speed: (base + flat) × (1 + % bonuses) × (1 − the strongest slow × (1 − slow resist)), then the soft caps (wiki "Movement speed": only the strongest slow counts).
  • Dashes and blinks (abilities tagged dash or blink) use the dash range and speed from the game data (dashInfo; 1200 units/s when the data has none). A dash ends touching its target or at its range; its hits land when it arrives. A blink moves at once.
  • Knockbacks move the target away from the caster by the data distance over the airborne time (Janna R: to 875 units from her; Gragas R 900; Alistar W 700; Vayne E 475); pulls move it toward the caster. A placed knockback (Gragas R) is aimed away from the caster's team, or toward it for role "engage". Knockbacks whose distance neither source gives (Gragas E, Draven E, Ornn Q) only make the target airborne.

Roles (x.role)

"kite"Default for ranged champions. Targets the lowest-health enemy it can reach (else the nearest). Backs off from any shorter-ranged enemy inside its attack range between attacks, uses dashes and blinks to escape such an enemy, and uses hard crowd control first on enemies diving an ally (peel). Knockbacks are held for peel.
"dive"Default for melee champions. Walks or dashes to the lowest-health enemy and uses everything on it, except knockbacks, which it holds to peel an enemy diving an ally.
"engage"Like dive, but also uses knockbacks offensively at once (placed ones push the target into its team).
"peel"Holds every hard crowd control ability for enemies that reach an ally they are outranged by (or itself), guards the rearmost ranged ally when nobody is diving.
"fight"Targets the lowest-health enemy it can reach, walks to attack range, no kiting. Every "kite" champion, default or set with x.role, uses it under fight(…, kite: false).

An enemy "dives" ally A when it is within its own attack range (+ 50) of A and A's attack range is longer. Spell shields, Morgana E and cleanses react perfectly: Sivir E and Nocturne W are raised as a hostile ability lands; Morgana E is cast on the ally a hard crowd control is about to land on (if in range); Quicksilver Sash and Mercurial Scimitar cleanse as soon as a cleansable crowd control lands; Mikael's Blessing is used on a crowd-controlled ally.

Source: wiki "Types of Crowd Control" (summary table). Tenacity (wiki "Tenacity") shortens every type except airborne, suppression and drowsy, to no less than 0.3 s; items, elixirs and the rune shard stack multiplicatively (1 − (1 − a)(1 − b)…). Quicksilver removes everything except airborne (suppression included); Mikael's Blessing removes stuns, roots, silences, polymorphs, forced actions, sleep and slows, not suppression or airborne. Spell shields (Banshee's Veil, Edge of Night, Verdant Barrier, Sivir E, Nocturne W) block one whole ability, crowd control included.

Where the numbers come from

src/cc_export.py reads which crowd control each ability applies from the wiki ability text ({{tip|stun|…}} for {{fd|1}} seconds, knock back 900 units, slowed by 80%) and takes the value from the game data (StunDuration, RootDuration, KnockupDuration, KnockbackDistance, SlowAmount, …) when one exists and agrees with the wiki at every rank; otherwise the wiki's value, and the working says so. Where they disagree the wiki value is used and the game data value is shown (python src/cc_export.py lists them: KSante Q, Rammus Q, Urgot E, Hwei R, Lissandra R, Maokai Q…). Durations that grow with distance travelled (Xerath E 0.75–2.25 s, Braum R) are assumed linear up to the ability's reach; charge-dependent ones (Janna Q, K'Sante W, Sion Q) use the uncharged value, since fights cast at once. Kennen's Mark of the Storm is modelled: every ability hit marks, the third mark stuns 1.25 s (0.5 s if stunned by it within 6 s; game data), Slicing Maelstrom marks each target up to 3 times. Effects the wiki makes conditional on terrain (Vayne E stun, Poppy E stun, Ornn E) are left out, as are effects with no known duration (the assumptions list each one). Braum R: the first target's knock-up grows from 0.6 s with distance, assumed linear up to the ability's reach.

Damage, healing, stats

  • Stats at a level: base + growth × (level − 1) × (0.7025 + 0.0175 × (level − 1)), the game's formula.
  • Ability formulas are evaluated from the game's calculation trees: per-rank values, stat ratios (total, bonus or base), level curves, sums, products and clamps. Stack-based parts count as 0 stacks (noted).
  • Resistances: percent penetration first, then flat (lethality is flat armor penetration); damage × 100 ÷ (100 + resist), or 2 − 100 ÷ (100 − resist) below zero.
  • Adaptive runes give AD when bonus AD exceeds AP and AP when AP exceeds bonus AD (1 adaptive = 0.6 AD or 1 AP). The AP compared includes Rabadon's +30%, which then also amplifies adaptive AP. A tie (e.g. no items) goes to the champion's adaptive type from the game files (Zed: AD, Syndra: AP). Adaptive damage is physical or magic by the same test.
  • Abilities that apply on-hit effects (the wiki's "Attack effects" list: Katarina's Shunpo, Sinister Steel and Death Lotus, Ezreal Q, Fiora Q, Gangplank Q, Irelia Q, Yasuo Q, Yone Q…) trigger on-hit items at the listed effectiveness (Death Lotus 25/30/35%, Master Yi Q 18.75%, Urgot W 50%…). Channels like Death Lotus are separate hits (15 daggers per target). Ones that also trigger on-attack effects count as basic attacks for Kraken Slayer, Terminus and Hullbreaker stacks. On-hit-only ones stack and consume Kraken's Bring It Down, per the wiki's Kraken Slayer page, but build no Terminus stacks (assumed).
  • Critical strikes deal 200% (base; Infinity Edge +30% = 230%). Ashe's crits deal no bonus damage.
  • Attack speed is capped at 3.003 (one attack per 0.333 s); Bel'Veth has no cap. Cap exceptions that only last during an ability (Jinx, Kennen, Varus, Sion, Zeri) aren't modelled.
  • Move speed = (base + flat) × (1 + % bonuses), then soft caps: above 415 → × 0.8 + 83, above 490 → × 0.5 + 230.
  • Item limits from the game's item data: one pair of boots, one Blight item (Void Staff, Cryptbloom, Terminus…), one Hydra, one Spellblade, no two copies of a legendary, and so on. Breaking one is an error.
  • Cooldowns: base × 100 ÷ (100 + ability haste). Haste that one ability gives another (Syndra R: Dark Sphere +10 per R rank) is included.
  • Heals: formula × (1 + heal & shield power) × (1 + healing received), capped at missing health.

Limits

  • A proof holds for the model, not the live game. The assumptions list says exactly where the two can differ.
  • Tooltip-derived tags and damage types can be wrong; check the evidence and correct with addTag / removeTag.
  • Champion-specific mechanics (Zed's shadows, stored damage, stacking passives, empowered recasts) are only as good as the tooltip formula.
  • Fights are one-dimensional: no terrain, walls, flanks or body blocking, and area abilities catch everyone within their radius on the line (2-D spacing would catch fewer). Mana is ignored. Physics checks assume perfect aim and a straight-line dodge.
